# Corporate RAG Assistant

Корпоративный ассистент по PDF-инструкциям и Wiki. Он отвечает только по найденному контексту, указывает источники и отказывается отвечать при недостаточных данных.

## Архитектура

| Компонент | Реализация |
|---|---|
| Парсинг PDF | PyMuPDF |
| Парсинг HTML | BeautifulSoup |
| Индексация | LlamaIndex |
| Векторная база | Qdrant |
| Embeddings | BAAI/bge-m3 |
| Поиск | Dense + BM25 + RRF + Cross-Encoder |
| LLM | Qwen3 14B — ответы ассистента и LLM-as-a-Judge |
| Сервер LLM | LM Studio, локальный OpenAI-совместимый API |
| Интерфейс | Gradio |

Граф выполнения:

```text
PDF / HTML → PyMuPDF / BeautifulSoup → чанки + metadata
→ LlamaIndex + Qdrant → dense + BM25 → RRF → Cross-Encoder
→ LLM → ответ с точными цитатами
```

## Корпоративная база знаний

В `data/knowledge_base/` сохранены корпоративные документы в форматах PDF, HTML, Markdown и TXT. Каждый чанк хранит метаданные `source`, `page` (для PDF), `header` и `format`.

## Запуск

Для запуска нужны Python 3.12, [`uv`](https://docs.astral.sh/uv/), Docker и установленный [LM Studio](https://lmstudio.ai/).

Установите зависимости:

```bash
uv sync --extra dev
```

Создайте локальный файл `.env`:

```bash
cp .env.example .env
```

Загрузите Qwen3 14B в LM Studio и запустите Local Server на порту 1234. Затем запустите Qdrant, создайте индекс и откройте интерфейс:

```bash
docker compose up -d
uv run rag-index --reset
uv run rag-ui
```

Интерфейс будет доступен по адресу [http://127.0.0.1:7860](http://127.0.0.1:7860).

## Тестовый запуск

```bash
uv run pytest
uv run rag-evaluate
uv run rag-evaluate --with-ragas
```

`data/evaluation/golden_questions.json` содержит пять сценариев: прямой факт, точный термин, агрегация, конфликт архивной и действующей политики, Out-of-Domain. Скрипт считает `Recall@3` и `MRR@3`; с `--with-ragas` Qwen3 14B используется как LLM-as-a-Judge и оценивает Faithfulness, Answer Relevance, Context Precision и Context Recall.

### Результаты оценки

Полный запуск `uv run rag-evaluate --with-ragas` завершился со следующими результатами:

```json
{
  "Recall@3": 0.6,
  "MRR@3": 0.6,
  "ragas": {
    "faithfulness": 0.7083333333333334,
    "answer_relevancy": 0.6406861875490131,
    "context_precision_with_reference": 0.874999999925,
    "context_recall": 1.0,
    "evaluated_samples": {
      "faithfulness": 4,
      "answer_relevancy": 5,
      "context_precision_with_reference": 4,
      "context_recall": 4
    }
  }
}
```

`Recall@3` и `MRR@3` равны 0.6: ожидаемый источник попал в top-3 в трёх из пяти сценариев, но не всегда занимал верхнюю позицию. `Context Recall = 1.0` показывает, что для всех четырёх сценариев с релевантным контекстом retrieval покрыл факты из эталонного ответа. При этом `Faithfulness ≈ 0.71` и `Answer Relevancy ≈ 0.64` указывают, что главные зоны для улучшения — ранжирование фрагментов и точность использования контекста моделью.

## Анализ слабых мест и тестирование

Ниже приведены пять ручных прогонов интерфейса. Ссылки на источники выделены жирным.

### 1. Прямой факт с PDF-цитатой

**Запрос:** «Какова минимальная длина пароля корпоративной учётной записи?»

**Ответ ассистента:**

> Минимальная длина пароля корпоративной учётной записи составляет 14 символов **[06_information_security_policy.pdf, стр. 1]**.

**Извлечённые источники:**

- **[06_information_security_policy.pdf, стр. 1]** — Политика информационной безопасности ООО (score: 1.103)
- **[01_employee_handbook.md]** — 2. Рабочее время (score: -3.011)
- **[access-provisioning.html]** — Привилегированный доступ (score: -3.260)

**Итог:** пройден. Факт и номер физической страницы PDF корректны.

### 2. Агрегация фактов с разных страниц

**Запрос:** «В какие дни сотрудники должны быть в офисе и за сколько заранее нужно подать запрос на удалённый день?»

**Ответ ассистента:**

> Сотрудники должны быть в офисе в дни, определённые совместно с руководителем с учётом командных встреч и задач, требующих присутствия в офисе **[02_remote_work_policy.md]**. Запрос на удалённый день нужно подать не позднее чем за 2 дня до начала выбранного периода **[Политика_гибридной_работы_2026.pdf, стр. 2]**.

**Извлечённые источники:**

- **[Политика_гибридной_работы_2026.pdf, стр. 2]** — Оформление удалённого дня (score: 4.106)
- **[02_remote_work_policy.md]** — 1. Общие правила (score: 2.028)
- **[01_employee_handbook.md]** — 4. Удалённая работа (score: 0.348)

**Итог:** не пройден. Модель поставила две ссылки, но не назвала обязательные офисные дни из актуальной политики 2026 года — вторник, среду и четверг со страницы 1.

### 3. Out-of-Domain: защита от галлюцинаций

**Запрос:** «Какой ежемесячный лимит компенсации обедов для сотрудников?»

**Ответ ассистента:**

> Я не знаю.

**Извлечённые источники:** «Нет источников: ответ сформирован как отказ.»

**Итог:** пройден. Ассистент не придумал факт, документ или номер страницы.

### 4. Широкий многофактный запрос

**Запрос:** «Составь подробную памятку по требованиям политики информационной безопасности: минимальная длина пароля, MFA и VPN, блокировка экрана и обновления, использование внешних ИИ-сервисов и первые действия при инциденте.»

**Ответ ассистента:**

> Я не знаю.

**Извлечённые источники:** «Нет источников: ответ сформирован как отказ.»

**Итог:** частично пройден. Система не галлюцинировала, но широкий запрос не прошёл retrieval/rerank, поэтому проверить сохранность ссылок в длинном ответе не удалось.

### 5. Точечный многофактный запрос

**Запрос:** «Перечисли требования политики ИБ: минимальную длину пароля, обязательность MFA для VPN, время автоматической блокировки экрана и срок установки обновлений безопасности.»

**Ответ ассистента:**

> Минимальная длина пароля не указана в предоставленном контексте **[06_information_security_policy.pdf, стр. 2]**.
>
> Обязательность MFA для VPN: «Многофакторная аутентификация обязательна для VPN» **[06_information_security_policy.pdf, стр. 2]**.
>
> Время автоматической блокировки экрана: «автоматическая блокировка экрана должна включаться не позднее чем через пять минут бездействия» **[06_information_security_policy.pdf, стр. 2]**.
>
> Срок установки обновлений безопасности: «Обновления безопасности устанавливаются в срок до 72 часов после получения уведомления ИТ-службы» **[06_information_security_policy.pdf, стр. 2]**.

**Извлечённые источники:**

- **[06_information_security_policy.pdf, стр. 2]** — Многофакторная аутентификация обязательна для VPN, корпоративной почты, CodeForge, VaultBox (score: 0.468)
- **[06_information_security_policy.pdf, стр. 2]** — Многофакторная аутентификация обязательна для VPN, корпоративной почты, CodeForge, VaultBox (score: -5.190)
- **[access-provisioning.html]** — Привилегированный доступ (score: -5.252)

**Итог:** не пройден. Три факта со страницы 2 процитированы корректно, но факт «не менее 14 символов» находится на странице 1 и не был извлечён. Ассистент ошибочно заявил, что сведений нет, и сопроводил это нерелевантной ссылкой.

## Отчёт и анализ

### Вывод по галлюцинациям

Системе удалось существенно снизить риск галлюцинаций, но не устранить его полностью. В Out-of-Domain сценарии она корректно отказалась отвечать и не выдумала источники. В прямом вопросе ссылка на PDF и страница были точными. Это обеспечивают строгий системный промпт, передача в контекст готовой ссылки из метаданных и порог rerank перед генерацией.

Главный оставшийся риск связан не с выдумыванием несуществующих страниц, а с неполным retrieval. В тестах модель либо отказалась при слишком широком запросе, либо не получила страницу 1 и поэтому ошибочно заявила, что факт отсутствует. Следовательно, ссылке можно доверять только в пределах найденного контекста: корректный формат ссылки не гарантирует полноту ответа. Для улучшения нужны приоритизация актуальных документов, более точный rerank и проверка покрытия всех частей составного вопроса.

### Номера страниц PDF

В тестовых PDF номера страниц указываются корректно: система сохраняет номер физической страницы файла, и он совпал с проверенными страницами документов. Возможное расхождение относится к другим PDF с обложкой, оглавлением или вводными листами: программа посчитает листы файла, а напечатанный внизу документа номер страницы может быть меньше.

### Извлечение метаданных при парсинге PDF

PDF обрабатывается постранично: номер физической страницы из документа сохраняется в поле `page` метаданных чанка.

```python
with pymupdf.open(path) as document:
    for page_number, page in enumerate(document, start=1):
        text = page.get_text("text").strip()
        if not text:
            continue
        lines = [line.strip() for line in text.splitlines() if line.strip()]
        current_header = _header(lines, current_header)
        result.append(
            Chunk(
                text=text,
                metadata={
                    "source": path.name,
                    "page": page_number,
                    "header": current_header,
                    "format": "pdf",
                    **infer_business_metadata(text, path.name),
                },
            )
        )
```

```text
Ты — корпоративный ассистент. Отвечай только на основе предоставленного контекста.
Если в контексте нет достаточных оснований, ответь ровно: «Я не знаю».
Не используй внешние знания и не придумывай факты, документы или страницы.
Каждый фактический тезис сопровождай ссылкой из контекста строго в формате
[Название файла, стр. X] или [Название Wiki-статьи]. Не показывай ход рассуждений.
```
